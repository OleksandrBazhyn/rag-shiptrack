# ShipTrack: розгортання та мережа

## Місце розгортання
Система розгортається в публічній хмарі Google Cloud у регіоні europe-central2 (Варшава) з резервними копіями в регіоні europe-west3 (Франкфурт). Хмарне розгортання обрано через стійкість до відключень електроенергії, еластичність під сезонні піки та відсутність потреби у власному адміністраторі серверів.

## Бізнес-локації та способи доступу
- Офіс служби: керівник, диспетчери, бухгалтерія, адміністратор. Вебкабінет на робочих місцях, дротовий інтернет із резервним мобільним каналом.
- Сортувальні склади (2): працівники складу. Термінали збору даних через Wi-Fi складу, резервний LTE-модем.
- Місто (польові умови): кур'єри. Мобільний застосунок через мобільний інтернет, автономна робота за відсутності зв'язку.
- Офіси магазинів (віддалено): менеджери магазинів та інформаційні системи магазинів. Вебкабінет та API через інтернет.
- Місце перебування одержувача: мобільна вебсторінка відстеження за посиланням.

## Мережева архітектура
- Усі зовнішні запити проходять через глобальний балансувальник навантаження (Cloud Load Balancing) з політиками Cloud Armor: захист від DDoS, обмеження частоти запитів, фільтрація типових атак.
- Статичні файли вебінтерфейсів доставляються через Cloud CDN, що прискорює сторінку відстеження на повільних мобільних мережах.
- Сервіси застосунку не зберігають стану й з'єднуються з базою даних і кешем лише через приватну мережу VPC (Serverless VPC Access). База даних і Redis не мають публічних IP-адрес.
- Вихідні з'єднання до банку, сервісу ПРРО та облікової системи виконуються через Cloud NAT зі статичною IP-адресою, яку постачальники вносять до білих списків.
- Адміністративний доступ до консолі та внутрішніх інструментів надається лише через Identity-Aware Proxy з корпоративною автентифікацією.
- Інфраструктура описується конфігураціями Terraform (правила брандмауера, DNS-записи).
